# Scope: LabRat Nerds forum overhaul (roadmap R27)

Inspiration: the owner's archived copy of the real forum that inspired it (a Feb 2015 snapshot of the LabTech Geek board index). Notes below are from that page. Brand rule: our forum is LabRat Nerds, an invented parody; real products appear only as things people talk about.

## What the real board looked like
- Tagline "Automating the World"; a disclaimer that the site is NOT affiliated with the software vendor, information is provided as-is, test all scripts on a lab system before production ("including information, plugins and scripts provided by off duty vendor employees").
- A board index with a header row (Topics / Posts / Last post), each board with a one-line description, topic and post counts and a "Last post: Re: <title> by <user>, <date>".
- Boards (and sizes): General Discussions (331 topics, 1,621 posts), Community (external sites and musing), Plugin Playground (122 / 2,338, with sub-forums Custom Tabs and Dashing), Advanced Configurations ("crazy modifications and semi-hidden features"), Cloud Platform (5 topics), Configuration Tips, Cool Tools ("command line tools, scripts and PowerShell"), Dataview Exchange (share and build dataviews), Hardware Monitoring ("tools and SNMP OIDs"), Feature Requests ("let us know what would make your job even easier"), Redirectors / Tunnels / VNC, Reporting ("reports, report ideas and some SQL"), Script Exchange (the biggest: 319 topics), a **NEW** Vendor Lounge (only approved vendors can post; 0 topics), a VIP Area "for vendor employees ONLY", Plugin Development, and Exchange Help.
- Footer statistics: total posts 8,408, total topics 1,296, total members 5,296, our newest member <name>; "last visit was" and "it is currently" clock lines.
- Thread titles were practical and slightly rough: "Count Patching Percentage", "Ninite Solution - Seamlessly Integrating Ninite and ...", "RAID Monitoring", "Cloud Server access", "From (old remote tool) to ScreenConnect", "I need to detect files with Double extensions", "Service Plan Overview", "Agents not reporting in", "Acronis", "Windows Command Prompt (Working)", "Bad Performance % in Health Report", "Remove Retired Asset Duplicates of Active Agents for (PSA)", "USER WARNING / BANNED LOGS", "Finding user logged into control center".
- Tone: helpful strangers sharing scripts, "(Working)" and "Re:" prefixes, vendor and fan blend, no drama.

## What we have today
`Nerds` autoload (`nerds.gd`, desktop app NERDS): 10 thread titles in `DEFAULT_THREADS` (5 shown a day; READ = 2 XP, ANSWER needs the skill level: 4 XP and +2 karma), jokes, ranks LURKER / MEMBER / REGULAR / GURU, and the IRC `#labratnerds` call-a-friend help. There is no board structure, no counts, no last-post lines.

## Proposal: make it feel like a real board
1. **Board index screen** (the NERDS app's home): the header "LABRAT NERDS - AUTOMATING THE BURROW" with the not-affiliated disclaimer; parody boards with description, topic / post counts that grow slowly with the day, and a "last post: Re: <title> by <nick>, <time>" line drawn from the live thread list and the cast's nicks. Parody board names: General Squeaks, The Burrow (community), Plugin Sandbox (sub-forums Custom Tabs and Dashboards), Advanced Configs, Cloud Burrow, Config Tips, Cool Tools (command line and PowerShell), Dataview Swap, Hardware Monitoring (SNMP OIDs), Feature Requests, Remote Control (redirectors, tunnels, VNC), Reporting, Script Swap, **NEW** Vendor Lounge, VIP Area (employees only: locked, with a joke), Plugin Development.
2. **Boards map to skills and systems** so browsing teaches something: Script Swap and Cool Tools = PowerShell (the Academy and the `SCRIPT: THIS CLIENT` perk), Hardware Monitoring = networking (the closet and patch panel), Config Tips and Advanced Configs = servers, Reporting and Dataview Swap = the owner Boardroom and the planned metrics dashboard (R20: tie in, "Dashboards" is the plugin sub-forum), Remote Control = RMM sessions and the RDP story, Feature Requests = a place to vote (karma flavour), Vendor Lounge = the Rodent Nation vendors posting ads (ties to the SCAN MY BADGE follow-up emails).
3. **More threads**: grow from 10 to about 60 titles across the boards (4 to 6 each, period-correct 2013-14, practical and slightly rough, `Re:` prefixes, sticky announcements such as "Forum rules" and "How to post a script"), each with skill, level and a short fake post and one or two replies that the player reads before answering (a one-line twist per thread makes READ worth it). Example titles in our parody: "Detect files with double extensions (invoice.pdf.exe)", "Count patching percentage per client", "RAID monitoring on older servers (SNMP OID?)", "Agents not reporting in", "Disable Java auto-update on XP boxes", "Nightly robocopy with an email report", "Bad performance % in the health report", "Cloud server access after the upgrade", "Moving off the old remote tool", "Patch Tuesday auto-approve rules", "Which backup alerts are noise?", "iFone 5 screen for the ticket app: please". All in the patchable tables (`story/strings.txt`).
4. **Footer statistics and clock**: total posts, topics, members and "our newest member" (a name that changes with the day and sometimes is the player's own nick after a first answer), plus "It is currently <game date>" using the game clock and a 2013-14 date.
5. **Posting**: ANSWER becomes a short post (a pick from options already used by the answer check) that appears as a post in the thread with your nick and rank; high karma unlocks a signature line and the VIP-area joke; a wrong answer gets a polite `Re:` correction from a nick (keeps the current -1 karma rule).
6. **Cozy Easy**: no karma loss on a wrong answer; the rest unchanged.

## Steps
1. Data: boards, a larger thread table, fake posts and replies, stats, patchable text (M).
2. Board index and thread list screens in the `Computer` NERDS app, wide / h / v layouts, scrolling, Controls navigation, mouse (M).
3. Posting and replies, karma, rank, newest-member and last-post logic with seeded randomness (S).
4. Tie-ins: Script Swap to the PowerShell perk, Dashboards board to R20, Vendor Lounge to the conference vendors (S).
5. Tests (the data model; layout shots at three formats), docs (S).

Risks: `computer.gd` is near the lint line cap, so the forum drawing should live in its own module (like the planned `dashboard.gd`); the 3x5 pixel font is small for long titles (clip with ellipses, two-line rows at v).
