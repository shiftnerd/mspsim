# Simulation soak (slug soak-sim)

Long bot runs of the simulation that fail on errors, stalls, growth and bad saves. Not balance. Files:

- `godot/tests/soak_lib.gd`: the library. `install_capture()` adds a `Logger` (`OS.add_logger`) that records every engine error, script error and `push_error` with the cell configuration that was running (`Capture.cfg`); `run_cell(spec)` plays one cell and returns `{cfg, ok, errors, stuck, flags, info, days, frames, saves, save_fail, resumes, resume_fail, nodes, secs}`.
- `godot/tests/soak_sim.gd`: the CLI (`-- --cells=... --tiers= --strats= --seeds= --first= --cover --chaos --reload=0|1 --resumes=N --minutes=N --ts=N --max_frames=N --out=FILE --skip=K --verbose --list --preset=fast`; the header lists every cell name). Prints a `SOAK ok|FAIL` line per cell, `SOAKERR` per captured error, `SOAKSTUCK` with the state dump, `SOAKSUM`. Stdout is buffered by Godot when redirected to a file: `--out=FILE` (one JSON line per finished cell) and `--verbose` (`SOAKDAY` lines on stderr) show progress while it runs.
- `godot/tests/soak_sim_smoke.gd`: the default-suite smoke test (the `fast_preset()` cells, about 25 s): a chaotic tech run with the morning reload, bowling, darts, and the every-key save ablation.
- `godot/tests/bot_lib.gd`: got `abort` (a hook ends the run at the next frame) and a `frame_hook` call in the sales loop.

Run (one Godot process at a time, from `godot/`):

    Godot --headless --fixed-fps 60 --path . -s res://tests/soak_sim.gd -- --cells=tech1,owner2 --cover --seeds=3 --resumes=20 --minutes=8 --out=FILE

A full tech run is 20 days, about 32 000 frames, 70 to 85 s on a quiet machine (several times that while other agents run Godot).

## What is checked

- Errors: every `Logger._log_error` (ERROR, SCRIPT ERROR, push_error) is a failure with the cell configuration; warnings are only counted. A `leaked` line at engine exit is printed after the harness is gone: check the tail of the log of a chunk for `leaked` / `ObjectDB` text.
- Stalls: no clock step, new day, answered card or closed ticket for `stuck_frames` (1500) frames: the state is dumped (`SOAKSTUCK`), the day is nudged shut once, a second stall aborts the run (`TIMEOUT`).
- Growth: node, object and orphan counts are sampled at each new day; failure when the last sample is over 15 % + 40 nodes (objects 15 % + 200) above the day-3 sample, or orphans climb by over 25.
- Save and reload (`reload`): at the morning of every day the end-of-day save the game wrote is read, `Campaign.continue_game` loads it, and day, rep, scars, cash, year and skills must equal the file (XP may rise: the day-begin hooks run again on a load, e.g. the conference trip pays its XP the morning after; it may not fall).
- Resume (`--resumes=N`): N random frames take `Campaign.snapshot()`, then `continue_game(mode, true)`; day, rep, cash, scars, clock, open tickets, closed count, score, skills, energy and owner cash must be unchanged.
- `saves` cells: a run with reload plus resumes, quit to title and CONTINUE, a new campaign over an old save, delete slot. `ablate` cells: a real save is written, then every section, every key and every key of every dictionary under `campaign` is deleted in turn and loaded (about 280 loads per mode; an old save lacks whatever was added later), then a day-only file and an empty file.
- Chaos (`chaos`, or the chaotic strategy with `--chaos`): random phone / Computer open and close, a card answered at random, the day skipped to its end, `Msp.pace` x0.5-2, `Difficulty.set_tier`, `cycle_day_scale`, clock jumps.

## Decisions made

- Mid-day resume is exercised in the running bot (the hook calls `snapshot` and `continue_game(mode, true)` in place) rather than through a title-screen round trip; the title round trip is in the `saves` cell.
- "Old save fixtures from git history" are generated by deleting sections and keys from a current save (any old format is a subset of the current one), not by checking out old commits.
- Owner runs use `ts=4` (the owner bot loses weeks above that). Owner and sales have no `mixed` bot: it maps to careful on even seeds and lazy on odd ones.
- Outings are played in panel mode (`panel: true`) by a key-mashing bot with 4 extra `Outings.tick` calls a frame; they end by their own timers or rounds. Room mode is available with `"room": true` in a cell.

## Runs so far

The machine was shared with many other Godot processes and a background run got a fraction of one core, so only a small slice of the matrix ran.

Clean (no error, stall, growth flag, save or resume mismatch): tech Y1 easy careful s1, easy lazy s2, easy mixed s3 (all 20 days, 19 reloads, 19-20 resumes each); tech Y1 with chaos, easy careful / lazy / mixed / chaotic (reload and resumes; chaos drives the player to FIRED endings in 6-11 days, which exercises the fired path); tech Y2 easy careful, normal lazy, hard mixed, normal chaotic; tech Y3 easy careful; the `ablate tech` cell (283 ablated saves load, 0 refused); `soak_sim_smoke` (4 cells, 22 s). About 15 campaign runs, about 150 game-days, 0 errors from the game. The node count is flat at 214 on the main floor all run (176 on the conference day), objects +2 to +30 over 20 days, orphans 0.

Not run (the cells exist, the time did not): owner Y1-3, sales Y1-3, service Y1-3, other tech Y3 tiers, co-op, Free Play per mutator, the outing matrix (the `outings` list: bowling, karaoke x3 songs, dinner variety on / off, cornhole, grill, darts, chair x3 events, paintball day / night, escape 4 themes x 9 clue recipes), nerf, printer, `saves`, `ablate` for owner / sales / service. Continue with `--cells=... --skip=K` in chunks of `--minutes=8`. A first run of the `outings` cells is the most likely place for real findings: the mash bot has only been tried on bowling and darts.

Tips: kill a stale Godot before starting a chunk (`timeout` does not kill it on Windows); check the CPU time of a background run before assuming a hang.
