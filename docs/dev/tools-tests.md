### Layout audit and real clicks in tests (Q3 / Q4)
- `PixelFont.audit` (null = off) logs every `PixelFont.draw` inside a CanvasLayer with its rect in viewport pixels; `PixelFont.audit_report(fmt, overlaps)` returns `OFFSCREEN` lines (text outside the viewport) and `OVERLAP` lines. With env `LAYOUT_AUDIT=1` `Game._process` prints them during ANY test run (`LAYOUT_AUDIT=1 Godot --path godot -s res://tests/x_shots.gd -- --format=v`). `tests/layout_audit.gd` (renderer needed; `-- --only=title,floor --shots`) walks ~55 key screens in wide, h and v and fails on any off-screen text.
- `Game.click_at(ui_point)` / `hover_at(ui_point)` send a real mouse event through `Input.parse_input_event` at a logical UI point (via `Game.ui_to_window`). UI `_input` handlers must read `event.position`, not `get_viewport().get_mouse_position()` (the OS cursor). `tests/click_harness.gd` shows the pattern (title menu, card option, Computer app button); cards and the day report need a real-time wait (0.45 s) before a click lands.
- Layout rules found by the sweep: card options wrap instead of truncating; the day report drops to 6 px rows when it would not fit 128 px; the title menu uses two columns when the rows do not fit; the Boardroom BOOKS values wrap.
### Balance by bot playthrough (Q6; `tests/bot_lib.gd`, `bot_run.gd`, `tiers_balance.gd`; results in `docs/balance-notes.md`)
- **Bots**: `bot_lib.gd` plays any campaign (tech / owner / sales / service) at any tier with a strategy (careful / lazy / chaotic; tech also `proper` and `shortcut`) for one seed in compressed time and returns `{rep, score, ending, cls good|mid|bad, fired, info}`. `bot_run.gd` is the slow harness (one cell per process, `BOT` and `CELL` lines), `tiers_balance.gd` the smoke test (sales, tech, service; asserts careful easy >= normal >= hard and careful > lazy per tier). Owner must run at `ts=4` or lower. The older balance tools are unchanged.
- **Tier dials** (new `Difficulty.TABLE` keys, read with `Difficulty.cf(key)` which gives the normal number outside a campaign, and `cm("pace" | "sla")` which picks `tech.*` or `crew.*` by mode): ticket pace and SLA windows (`Msp._process`, `Mutators.sla`), the day report's reputation move (`Campaign._tier_rep`: `tech.gain/loss` for the tech campaign, `rep.gain/loss` for the others), `tech.alt_ret` (return chance of quick workarounds), `owner.cost` (weekly overhead), `sales.lead` (lead quality) and `service.trust` (trust lost). Normal is unchanged; `tests/difficulty.gd` lists every key at its normal value.
- **Alt fixes**: a workaround that comes back is rework (`Msp.spawn_return`: ticket flag `repeat`, client mood `RETURN_MOOD` -3; `close_ticket` gives `REPEAT_POINTS` 2 and no closed-ticket credit). Using it on everything costs about 10-15% of the score and a dozen SLA misses.

### Test runner and generator check (roadmap H1, H4, H6)
- **`python tools/run_tests.py [-j 4] [--timeout 600] [--list] [--all] [names/globs]`** runs headless tests in parallel (`godot/tests/*.gd`; no names = every regression test except screenshot / balance / harness scripts, see `SKIP` in the file). A test passes when the exit code is 0, no line starts with `FAIL` (an `ok ... FAIL` line like t2's does not count), no `failures=N>0` and no `SCRIPT ERROR`. Prints a table and the tail of each failure; logs go to `%TEMP%/run_tests/<test>.log` (`--logdir`). A fresh worktree needs one `Godot --headless --path godot --import` first (no `.godot` cache = missing animations and every test fails). `*_shots.gd` tests save PNGs to `user://` and need a renderer (not `--headless`); most take `-- --format=wide|h|v`. Tests must use their own save paths (`user://test_%d_...` with the process id, also for `Difficulty.settings_path` and `Phone.save_path`), so never add a test that writes a fixed `user://` name.
- **`python -I tools/check_generator.py [--keep] [--scratch DIR]`** copies the tracked `tools/` + `godot/` into a scratch directory (the Godot import step is disabled there), runs `make_godot.py` THERE and diffs the generated project.godot / scenes / characters / scripts against the working tree (exit 1 on differences). Never run `make_godot.py` in the real tree: the committed scripts carry hand edits that were ported into the generator, and the check keeps them in sync. Scripts are compared after running `gdformat` on both sides to a fixpoint (the committed ones were hand-edited after the last format pass, line endings are ignored). Hand-edit a `.gd` and the same text in `tools/make_godot.py` in the same commit, then rerun the check.

- gdlint: `gdlint scripts tests` from `godot/` is clean. `godot/gdlintrc` now sets max-line-length 190 and max-file-lines 4100; unused args are prefixed `_`, odd names renamed, and style rules the generated or test code breaks on purpose (class-definitions-order, max-returns, naming, comparison-with-itself, expression-not-assigned, duplicated-load) are switched off per file with a `# gdlint:disable=` header (scripts: in both the .gd and `make_godot.py`; `check_generator.py` 361/0). `gdformat` was not run in bulk.


### P6: heavy fixes in person, more ransomware exits, clever fixes in Free Play (`msp.gd`, `onsite.gd`, `computer.gd`; test `tests/p6.gd`)
- **ONSITE REIMAGE** (tech campaign only): `Msp.onsite_heavy(ep)` returns `reimage` / `new_profile` when the machine is a workstation whose problem has that heavy alt (`HEAVY_ONSITE`), the client has a site (`Onsite.has_site`) and visits are on (`Onsite.enabled`); Free Play and the owner / sales / service modes get nothing. The RMM session then shows an extra heavy-tinted button ONSITE REIMAGE (ONSITE PROFILE for a lockout). It only offers: the remote REIMAGE PC / REBUILD PROFILE stay. `Onsite.offer_reimage` opens a dispatch card with the drive time; GO runs the ordinary `_depart` with `reimage_job()` as the job (front desk PC, TOOLS > DIAGNOSE AND FIX, option ASK THEM TO SAVE, THEN REIMAGE: 0.75 h, always works, 5 servers XP; the second option leaves and costs mood like any failed onsite option). The ticket you were working is the job (its `fix` stays the original, so it is not an `onsite_` ticket); the trip adds the round trip to its own SLA, ages the other tickets as usual, and `_reimage_done` clears `unsaved` / `asked` (nothing lost, no I LOST MY WORK mail), gives client mood `tech.onsite_mood` (3 / 2 / 1 by tier) and marks `method = "onsite"`.
- **Hard tier makes the remote version worse, only when the onsite offer exists**: `Difficulty.TABLE` `tech.heavy_fail` (0 / 0 / 0.25: the last step fails, "THE IMAGE FAILED AT 90 PERCENT", rolled on the seeded `msp.fix` stream) and `tech.heavy_slow` (1 / 1 / 1.3 x job time, applied in `Computer._start_job`). Normal and easy are exactly as before (heavy fixes still skip the generic "did not stick" roll).
- **Ransomware exits** (`Msp._rmm_special` routes them, RMM buttons only on a ransomed machine): ASK VENDOR (`vendor`, button VENDOR VERSIONS): 50% (`VENDOR_ODDS`) an old version restores everything (`Story.flags.ransom = "vendor"`, score -1, closes normally), else the vendor has nothing and it cannot be asked again; ISOLATE+REBUILD (`rebuild`): always works, 4x job time, score -10, reputation -4, client mood -8, flag `rebuilt`, closes for 4; CALL INSURER (`insurer`, only where `Msp.cyber_insured(client)`: seeded 50% per client and run via `Difficulty.rng_for("msp.insured", client)`): 65% (`INSURER_ODDS`) the recovery firm decrypts (flag `insured`, score -4, rep -1, closes for 4), else the claim is denied (client mood -2, once). The old ones are unchanged. `Msp.RANSOM_LABELS` (review / owner year-end line) and `RANSOM_LINES` (owner text to Alan) cover all seven endings; the day-14 Spence callback has mails for the three new ones; `goal_parts` counts `vendor` as a clean year.
- **Owner campaign** card `ransom_options` has six options now: pay $500, shadow copies, vendor support $150 (50%), isolate and rebuild $300 (sure, -2 rep, -8 law firm mood), the cyber-insurance line $250 deductible (65%, greyed with NO POLICY via the new option key `policy` when `cyber_insured(Story.RANSOM_CLIENT)` is false), accept the loss. New strings are in `story/strings.txt` (after changing a card's option order by hand, check the old keys: `--sync` keeps edited text by key, so a stale `options.N.label` overrides the code).
- **Clever fixes in Free Play**: `Msp.alt_unlocked` uses `FREE_PLAY_LEVEL` (3, every gate is 3 or less) outside a campaign, so PRINT TO COPIER, UNLOCK-ADACCOUNT, CLEANUP SCRIPT, SPYHUNT, SAFE MODE and FIND HUNG SERVICE show in Free Play; campaigns still use the real levels. Free Play fixes take no time, so nothing else changed.

## Dev workflow tools (Nov 2026, from the multi-agent course review)

- `tools/port_edit.py`: the dual edit (generator text + real file) in one atomic step. `edit SPEC.json [--dry-run]` takes `{"edits": [{"file": "scripts/x.gd", "old": "...", "new": "..."}]}` written in the generator's 4-space form; each `old` must match exactly once in the generator block and, after the tab conversion, once in the real file. `add FILE [--after scripts/y.gd]` embeds a new real file as a generator block, `resync FILE` replaces a block with the real file (only for files you created by hand), `check` runs `git add -N` and the generator check.
- `tests/canon_text.gd`: scans every string literal in `godot/scripts/*.gd` (about 55 000) for `Strings.BANNED` (the 2013-14 era words, whole words only) and for real MSP vendors (its `BRANDS` list; `ALLOW` holds deliberate uses). `strings.gd` keeps scanning `story/strings.txt`.
- `run_tests.py` no longer skips `layout_audit.gd` and `click_harness.gd`.
- `tools/art_lint.py` (needs Pillow): style check of exported PNGs under `godot/assets` (no semi-transparent pixels, colour limits per kind, character sheets 80 px high / multiple of 64 wide with at least 85 % of the silhouette edge in the outline colour #17121F). Default: the files changed since HEAD; `--all` for everything (about 50 s; all 475 files pass today, the roster sits at 89 to 96 % outline share). Exceptions go in `tools/art_lint_allow.txt`. The `art-lint` agent in `.claude/agents` does the Aseprite-side checks.
- `tools/balance_baseline.py`: runs `tests/tiers_balance.gd` (about 3 minutes) and compares its `BOT ...` lines with `docs/dev/balance_baseline.json` (rep within 20 points, score within 35 %); `--update` rewrites the baseline on purpose. The bots are not fully deterministic (a seed moves several points between runs) and the test's own ordering asserts (careful beats lazy, easy >= normal >= hard) fail now and then, e.g. `tech easy: careful beats lazy (100 vs 100)`: the cozy easy tier lets the lazy bot reach 100 reputation too. Those asserts were hidden while the test sat in the SKIP list; the drift table is the signal to watch.
- `PAINT_DEBUG=1` in the environment makes the paintball field draw every unit's blackboard line (role, goal x, target) under it (`PaintballGame.debug_line`).
- `.github/workflows/tests.yml` runs lint, the generator check and the suite (`--retry 1`) on push and pull requests; written from the local commands and not yet run on GitHub.
- `.claude/agents/`: `scope-reviewer` (read-only feature review before building), `generator-porter` (finds and fixes generator / real file drift), `art-lint` (Aseprite-side style check).
