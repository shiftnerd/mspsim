# Audio, creator and polish

(Moved verbatim from CLAUDE.md. Headings below keep their original levels.)


### Audio (P4: `sfx.gd`, autoload `Sfx`; test `tests/sfx.gd`)
- There are no sound files. `Sfx` synthesises every sound the first time it is asked for (square / triangle / saw / sine / noise layers from the `SOUNDS` table, 16 bit mono `AudioStreamWAV` at 22050 Hz, cached) and plays it through a pool of 8 `AudioStreamPlayer`s. `Sfx.play(id)`, `Sfx.play_near(id, node)` (softer with distance from the player, used by the desk phone ring, headset, coffee machine and bell), `Sfx.play_grade("S")`, `Sfx.play_music("title" | "day")`. Autoload `Sfx` is last in the list (it connects to `Msp` and `Campaign` signals in `_ready`).
- Songs (`SONGS`): a 4 bar lo-fi loop (triangle bass, soft square arpeggio, hat, sparse seeded pentatonic melody, 11025 Hz, bit-crushed) per `seed`; same seed = same loop. The title screen starts "title", `Campaign.day_started` starts "day". Quiet by default (`music_volume` 0.25).
- Hooks (one line each): Msp `ticket_added` / `text_received` signals, `Msp.close_ticket` (ding), SLA breach in `Msp._process` (buzz), `Msp._mail` for mail without a ticket, `Cards` open / pick / disabled pick (error) / selection move (tick), `DayReport.show_report` (grade jingle), `Phone.open` / `Computer.open`, a key tick in `Computer._input`, `Fx` desk phone ring (every 3.5 s while ringing) / headset / coffee / `ring` (bell), `Nerf._spawn` / `dart_hit` / out of darts, `ChairRoll` squeak, clunk and bump, `Outings` bowl roll / strike and karaoke hit / miss, `PrinterGame._pull` tear (jam). The `footstep` sound exists but is not hooked.
- Accessibility rule: no mechanic depends on sound. Every sound sits next to a cue that already existed (toast, bubble, ring animation, flash, the card or report itself).
- Settings: `Sfx.volume` (0.7), `Sfx.music_volume` (0.25), `Sfx.muted`, saved in the `[audio]` section of `user://mspsim_settings.cfg` (`Sfx.settings_path`, same file as `Difficulty`; each class keeps the other's section). M toggles mute anywhere nothing else takes the key (`_unhandled_input`) and shows a SOUND ON / OFF toast; the day 1 hint line lists it, and the title menu shows `SOUND ON  M` in the corner. There are no sliders yet: edit the file or call `set_volume` / `set_music_volume`.
- Headless / tests: `Sfx.silent` is true under the headless display server (tests may set it); nothing touches an audio device then, but `Sfx.played` records every requested id and `Sfx.heard` the ones that were not muted (`clear_log()` empties both; 400 max). A test that uses `settings_path` must set it to `user://test_<pid>_...` first, like `Difficulty`.
- Real assets later: `Sfx.stream(id)` and `Sfx.music_stream(id)` are the only places that decide what a sound is. Load `res://assets/audio/<id>.ogg` (or .wav) there when it exists and fall back to the synth; no caller changes. 2013-14 rule: no brand names and no sampled copyrighted music.

### Character creator, level 1: colours, and level 2 step 1: hairstyles (roadmap R15; `scripts/look.gd` autoload `Look`, test `tests/creator.gd`, shots `tests/creator_shots.gd`)
- **What it is**: the creator IS the character select of the tech campaign and Free Play (R35: it opens straight into the CREATE step, `step = "create"`, first page of `flow()`; not owner, sales or service: those play a cast member and keep their cards). Its first row is START < MY LOOK > (the ready-made people and saved looks, see "Logo + title screen"; hidden when the list has one entry, tests set `cs.ids = ["custom"]` to keep row indices), then rows NAME, STYLE (hairstyle, `< >` chips, Left / Right cycle), SKIN, HAIR, SHIRT, PANTS, SHOES and RANDOM / DONE (since level 3 step a these are on pages, see Layout below), a live idle preview, Up / Down rows, Left / Right change (NAME cycles suggested 2013-14 names), typing on the NAME row (letters, digits, space, dash; Backspace; max 10), Enter on RANDOM rolls, Enter elsewhere goes on, Esc / B goes back, mouse clicks on swatches / arrows / chips. All through `Controls.nav / confirm / back`, so a pad works (the name is by suggestions only on a pad). The summary line and start toast use the custom name ("TECH CAMPAIGN - ZOE - NEXXUS 5 - NORMAL").
- **No new art**: the custom person is `Look.BASE = "office_intern"` (cleanest palette, documented in "Palette") drawn through a palette-swap `canvas_item` shader (a `Shader` built from a string in `look.gd`, no shader file) on the player's `AnimatedSprite2D`, the select preview, and any NPC with `custom = true`. `Look.SOURCES` lists the 13 flat colours that are recoloured (skin f3b488 / d88a62 / b8663f, hair 9a5124 / c47a38, shirt 4f7fd0 / 3a62a8 / button bbd0f5, pants 3a3f66 / 2f3354 / 272b48, shoes 5a3522 / 4a2c1c); `Look.KEEPS` (outline and belt 17121f, eye white, pupil, brows, mouth, buckle, watch) are matched to themselves so they are never taken for a neighbouring shade. Match = nearest source inside RGB distance 0.03; the two hurt frames (25, 28) are every colour mixed 70% to white and are matched at 0.01 and mixed back. `Look.shade_of(base, role, level)` computes the shades from the chosen colour with the original pair's hue shift and saturation / value ratios, so the default look gives back the original sheet exactly. `Look.map_color()` is the GDScript twin of the shader (tests run it over every colour of both sheets).
- **The person**: `Look.look = {name, skin, hair, shirt, pants, shoes}` (6 digit hex, `SWATCHES` per role, `sanitize()` checks anything loaded), `Look.active` + `PLAYER.current_character == Look.BASE` = `is_custom()`. Everything keyed by character name sees plain `office_intern` (CHARACTERS, hands json, anim sheets, held items, Social / Lync / Talk); a custom person is never a cast member. The 1-7 number keys in Free Play set `Look.active = false` (stock people). `Look.randomize_look()` draws from `Difficulty.rng("creator")`, so the same run seed gives the same person.
- **Saved**: `campaign/character` stays `office_intern`; `campaign/look` holds the look plus `active` (`Look.to_dict / from_dict`; an old save has none and loads as a stock character). `user://mspsim_settings.cfg` `[look]` keeps the last look and `custom` (did the last new run use it), loaded by the title (`Look.load_settings`) so the next select screen opens on the MAKE YOUR OWN card with that look.
- **Hairstyles (level 2, owner decision: PREBAKE, not runtime composition)**: `look.hair_style` is one of `Look.HAIR_STYLES` = `side` (the intern's own hair, the default, so the sheet is plain `office_intern`, no duplicate files), `short` (site Alan's Hair layer), `receding` (office adult's), `curly` (casual Garrison's), then the drawn ones `long`, `bob`, `ponytail`, `bun` and `bald` (redrawn Nov 2026 as `grid` entries in `make_hair.lua`: `{y, x, "pattern"}` rows over an empty Hair layer, B base, C highlight, T outline colour, F the ear's skin shadow d88a62, B / C cells outlined automatically; the pulled-back cap is shared, the ponytail has a tie and a flared tail that hangs behind the head, the bun is a round ball with its own dark ring on the back of the crown, bald is the empty hair with a 1 px skin-shadow column down the back of the skull so the head reads round. The tail follows the rule `x >= 9 - 1.2 (y - 5)`: the death frames (31 / 32) shift the whole body by the union of the layers' boxes, and a tail further left than that moves the body 1 to 3 px against the intern's, which `tests/creator.gd` flags as covered eyes) and `spiky` (own cap with five upswept spikes, y 1 to 12). Ten styles in all, level 2 hair is complete. The ponytail hangs on the back of the head (left of a right-facing head, right of a left-facing one); the left file of every drawn style is the mirror of the right one. Every other style is a complete character built like any other: `tools/make_hair.lua` copies `office_intern_{right,left}.aseprite` to `custom_intern_<style>_{right,left}.aseprite` (repo root, like every character) with the donor's Hair layer recoloured to the intern hair colours 9a5124 / c47a38 (the donor's own base and highlight pixels are swapped, the outline kept; no new colour enters the sheets, so `Look.SOURCES` is unchanged), then `ROOT = "<checkout>/"; ONLY = {"custom_intern_short", ...}; dofile(".../tools/build_anims.lua")` builds the `_anim.aseprite` files, the 85-frame sheets and the hands json (the drawn styles also set `GHOST = {custom_intern_<style> = "office_intern"}` before `build_anims.lua` (the death frames shift the whole body by the union of the layers' boxes; the ghost adds the intern's hair box, so a style with less hair, bald above all, lands exactly where the intern does; `E.build`'s 5th argument, `an.ghost` in `anim.lua`), `ROOT` overrides the hard-coded main checkout path in `make_hair.lua` and `build_anims.lua`; use it in a worktree), the names are in `EXTRA_CHARACTERS` in `make_godot.py` (that writes `characters/custom_intern_<style>.tres`). `Look.sheet_for(character, custom, look_dict)` maps a look to the sheet name and `Look.frames_for()` loads `characters/<sheet>.tres`; `player.gd`, `npc.gd` (custom flag, with its own `custom_look` dict, empty = the player's) and the select preview use it, and `Look.apply(sprite, character, custom, look_dict)` still sets the palette shader, which runs unchanged on every sheet. There is no cache and no first-use hitch; the cost is about 33 KB per style per facing (fine for hair; it would multiply for shirts and pants, to be revisited then). Everything keyed by character name (hands json for held items, Social, Lync) still sees `office_intern`; the hair does not change the hand and ear table (tests check the json is identical). The head is the same on all styles, so with the ear no longer hidden by the intern's side-swept hair the short / receding / curly sheets show the face layer's ear as a darker skin patch; that is intended.
- **Adding a style** (data only): make its Hair layer (any 40x64 image in intern hair colours), add it to `STYLES` in `make_hair.lua` (or build the stills by hand), run both Lua scripts, add `custom_intern_<style>` to `EXTRA_CHARACTERS`, rerun `make_godot.py`, move the id from `Look.HAIR_PLANNED` to `Look.HAIR_STYLES`. The UI and `tests/creator.gd` follow `HAIR_STYLES`. `HAIR_PLANNED` is empty now. The ponytail tie stays outline-coloured (a shirt-colour tie would need a `Look.SOURCES` row). `make_hair.lua` STYLES entries are either donor recolours (`src`), `ext` rows over Alan's cap, `spans` (a whole drawn layer) or `empty`. A new shade needs a `Look.SOURCES` row (keep it about 0.06 RGB away from the KEEPS) and `tests/creator.gd _sheet_colors` already scans every shipped sheet.
- **Hair tests** (`tests/creator.gd`): per shipped style and facing: the same animations, frame counts, durations, speeds and loops as `office_intern.tres`, all 129 frames played, the sheet differs from the intern's only inside the head (the changed pixels sit within 6 px of the intern's hair / eye pixels and at most 30x30 per frame; `long` gets 16 px (12 before the R26 gestures tilt the head back) and 36x36, `ponytail` 8 px, because they hang below and behind the head), no eye white or pupil pixel changes, the hands json is identical; plus save / restore through the campaign and the settings file, an old save and old settings load as `side`, `sanitize()` rejects planned and unknown styles, seeded RANDOM keeps the old colour and name draws (the style is drawn last) and reaches every style, an NPC copy takes its own look dict. Compare sheets by alpha and by colour only where alpha > 0 (the importer changes the colour of transparent pixels). `layout_audit.gd` has `creator style row` screens.
- **Layout (level 3 step a)**: the create step has PAGES, as data: `charselect.gd` `CREATE_PAGES` = [{id, label, rows: [{kind, label, id}]}], kinds `name` (the text box), `choice` (a list in `Look.CHOICES[id]`, `< >` chips; hairstyle, pattern, shorts) and `swatch` (`Look.SWATCHES[id]`). Pages: LOOK (NAME, STYLE, SKIN, HAIR), CLOTHES (SHIRT, PATTERN, PANTS, BOTTOM = none / shorts, SHOES) and EXTRAS and WORK (the accessory pages, kind `acc`, see steps b to d below; a page with no rows has NO tab, `_pages()`). **Adding an option (the accessory agent's glasses, beard, hat, nametag, lanyard, watch) = one row dict in a page's `rows` plus its list in `Look.CHOICES`**; nothing indexes rows by position any more (`_page_rows()`, `create_row` = index into the page's rows, one past the last = the bottom row). Tab chips on the first row (clickable, kind `tab`), Q / E, Page Up / Down or a pad's LB / RB turn the page (`Controls` actions `page_prev` / `page_next`; on the NAME row Q and E are letters, the pad and Page Up / Down always turn), Up / Down rows, Left / Right values. The bottom row is RANDOM | PRESETS | DONE (`create_col`, Left / Right pick the button, Enter / A presses it; Enter on any other row still goes on). Wide 368x128 rows of 11 px (tabs + up to 5 rows + the bottom row = 7 lines, ends y 94), h 320x180 rows of 17, v 180x320 rows of 14. Audit screens `creator tech / free / random row / style row`, `creator clothes`, `creator clothes bottom row`, `creator presets`, `creator name grid` per format in `tests/layout_audit.gd` (`-- --shots` saves PNGs).
- **Presets**: three global slots (`Look.PRESET_SLOTS`, `Look.presets`, `save_preset / load_preset / load_presets`) in `user://mspsim_settings.cfg` section `[looks]`, `slot1` .. `slot3` each a sanitized look dict (its name is the slot name; junk or a missing section = empty slots; the `[look]` section and `campaign/look` are unchanged). PRESETS opens a modal (`create_modal = "presets"`): per slot a name box, a 5 colour strip, SAVE and LOAD chips, then CANCEL; Up / Down, Left / Right, Enter, Esc / B, mouse. LOAD wears the slot live in the preview (`_refresh_look`); an empty slot toasts.
- **Pad name entry**: A / confirm on the NAME row with a pad (or a click on the name box, for touch) opens a modal letter grid (`create_modal = "name"`, `grid_cells()`: A to Z and `-` in 3 rows of 9, then SP, DEL, DONE); arrows move, confirm types, DONE keeps, Back restores the name from before; at most `Look.MAX_NAME` = 10 characters (as always), no leading space; a keyboard still types while it is open. Enter on the NAME row with a keyboard still goes on.
- **Shader patterns and shorts (no art)**: `Look.look` has `pattern` (`Look.PATTERNS`: none, stripes, plaid, checks) and `shorts` (`Look.SHORTS`: none, shorts); both default to none (old saves, settings and presets load as none), are saved with the campaign, the settings and the presets, and reach NPC copies through `custom_look`. In the palette shader: the pixel position inside the frame cell comes from `UV / TEXTURE_PIXEL_SIZE` (64 px cells, so it works on the atlas frames of `AnimatedSprite2D`). PATTERN: only pixels that matched the shirt BASE or SHADE source (never the button tint, never a hurt flash match) get a second tone (`Look.tone_of`: a shirt with value over 0.6 is darkened 20% / 40%, otherwise mixed 25% / 50% to white) from `pattern_tone(px, py)` (stripes: 2 px horizontal bands; plaid: 2 px bands every 6 px both ways, crossings stronger; checks: 2 px chequerboard); a shirt pixel with a skin source colour within 3 px straight BELOW it (`SLEEVE_REACH`, sampled with `texture(TEXTURE, UV + k * TEXTURE_PIXEL_SIZE.y)`) is a sleeve over a forearm and is left alone. SHORTS: pants pixels (three tones) on or below the frame's hem row become the skin colour of the same level (`dst[level]`); the row comes from `Look.HEMS`, one number per frame (first pants row + 9, baked from `office_intern_right.png` by a throw-away script; the uniform `hems[123]` is all 255 when shorts are off; 255 = none for the lying death frames 29 to 34). Both are colour matches, so skin, outline, face, belt, buckle, shoes and the hurt flash frames (25, 28) cannot change by construction. `Look.map_pixel(img, x, y, look, pal)` is the GDScript twin (as `map_color` is for colours): keep it and the shader string in step. A new sheet frame count or a changed leg geometry needs `HEMS` regenerated (`tests/creator.gd` checks it against the sheet). **Known limits**: seated poses (frames 35 to 123 except the standing gestures) show only the thighs, so shorts do not show there (the trousers stay); the death frames 29 to 34 keep their trousers; an arm drawn across the shirt in the seated gestures can leave a few unpatterned pixels (skin below) or pattern a sleeve pixel that has no skin under it; the pattern is fixed to the frame cell, so it follows the 1 px breathing bob of the whole sprite but not the shirt alone. No hoodie entry (a second tone with no shape change did not read as a hoodie).
- **Tests (level 3 step a)**: `tests/creator.gd` `_level3` and `_check_masks` (pages by key, pad and mouse, rows per page, the bottom row, presets save / load / junk / old settings, the name grid, RANDOM's new draws come after the old ones, sanitize and save round trips, masks over all 129 frames of both facings: only shirt and trouser pixels change, nothing on flash frames, no sleeve patterned, shorts only below the hem and never on the death frames, legs exactly the skin tones, `HEMS` equals the sheet), `tests/charselect.gd` (the real screen). Contact strips of the poses with the real shader: `tests/creator_poses_shots.gd` (needs a renderer, writes `user://poses_<combo>_<facing>.png`).
- Level 2 (clothes, glasses, beard) and level 3 steps b to f are built, see the next sections and `docs/scope-character-creator-level3.md`. Not done: brows following the hair colour, a turnaround / walk preview.

### Character creator, level 3 step b: the head overlay, glasses and facial hair (roadmap R15; `scripts/head_gear.gd`, `tools/make_head_sheets.lua`, test `tests/accessories.gd`, scope `docs/scope-character-creator-level3.md`)
- **What it is**: accessories are NOT prebaked per hairstyle. They are small overlay sheets drawn by a `HeadGear` node over the custom person's head, read from the body sprite every frame, so the combinations multiply for free (10 hairstyles x 5 glasses x 5 beards with no extra characters). Shipped: GLASSES `thin` (Dan's thin rectangular), `thick` (heavy black), `round` (wire, metal by default), `aviator` (sunglasses; the dark lenses cover the eyes on purpose) and FACIAL HAIR `stubble`, `goatee`, `full`, `moustache`. Hats, nametag, lanyard and watch came in steps c and d (see the next section); their keys are in `Look.acc` like the others.
- **Data**: `Look.acc = {glasses, beard, hat, badge, lanyard, watch, beard_color, frame_color}`: style ids (`""` = none) plus the optional `beard_color` (empty = the hair colour) and `frame_color` (empty = the style's default, `Look.FRAME_STYLE`: round gold-brown, aviator silver, the rest the art's dark `1e1e26`), both 6 digit hex. Helpers for the UI rows to come: `Look.acc_ids(slot)` (none first), `set_acc(slot, id)` (false for an unknown id), `cycle_acc(slot, step)`, `sanitize_acc`, `default_acc`. `Look.acc` is saved with the look: `to_dict()` has an `acc` dict (the campaign `campaign/look`), the settings file `[look] acc` (a Dictionary value); an old save or settings file without it loads as none. NPC copies carry `custom_look["acc"]` (same shape; a look dict without `acc` wears none, an EMPTY dict wears the player's `Look.acc`). All the accessory code in `look.gd` is in blocks marked `LEVEL 3` (constants, `var acc`, the functions at the end) plus the `acc_dict` parameter of `palette` / `map_color` / `make_material` and the `_attach_gear` call in `apply`.
- **Colours**: four new `Look.SOURCES` rows (roles `frame` 1e1e26, `beard` 7d5a3a + shade 55402c, `stubble` e0a07a) and one new KEEP (`2f3d44`, the sunglasses lens; the white glint is the existing eye white). The beard art colours stand for "the hair colour" (or `beard_color`) and are never the real result; stubble is the skin colour mixed `STUBBLE_MIX` (0.4) toward the beard colour; frames are `frame_color`. They are 0.06 or more away from every KEEP and from each other source. The same shader recolours the overlay and handles the hurt flash (sheet frames 25 and 28 are baked flashed), so `HeadGear` gives its sprites `Look.make_material(look, acc)`. `tests/creator.gd` `_sheet_colors` scans the accessory sheets too and the default-look identity check skips the beard and stubble rows.
- **Source art**: `office/accessories.aseprite` (made by `tools/make_accessories.lua`, which holds the first drawing as row text; from then on edit the .aseprite): the intern's still (a reference, not read) plus one hidden layer per accessory named `<slot>_<id>` (`glasses_thin`, `beard_full`, ...) on the 40x64 canvas, RIGHT-facing, flat colours, no outline (every piece lies inside the head outline, the frames are dark ink coloured; an outline would also change the head's box). The intern's face (right-facing): eye whites near x19..23 / far x25..28 at y12..15, brows y11, flat cheek outline x29, mouth y19 x23..26, nose patch (28,16) (27..28,17), jaw outline y22. The glasses' top rim sits on y10 (the fringe) so the brows stay inside the lens; the round rings clip four eye-corner pixels. The left sheets are the mirror of the right art (`x -> 39 - x`).
- **Pipeline** (`tools/make_head_sheets.lua`, `ROOT = "<checkout>/"; REF = {...}; dofile(ROOT .. "tools/make_head_sheets.lua")` in `Aseprite.exe -b --script`, about 70 s): loads the intern still per facing, adds every accessory layer with `E.addLayer(an, name, image, true)` (`anim.lua`: a layer that is rotated and shifted like the head, `L.head`, but NOT measured in the death frames' union shift, `L.acc`; the accessory twin of `an.ghost`), renders all 129 poses with `E.render`, crops a fixed 32x32 cell centred on the Face layer's box of that pose (so it tracks tilt, hurt, death, dance, the gestures), pastes the `Arm Top` pixels over every accessory pixel they cover (a hand to the face, a scratch stays on top), and asserts nothing leaves the cell. Output in `godot/assets/accessories/`: `<slot>_<id>_<facing>.png` (123 cells wide x 32, 1.5 to 3 KB each, 16 files about 40 KB in all) and ONE `head_origin_<facing>.json` (123 `[x, y]`: the cell's top left in the 64x80 body frame, shared by every accessory). `REF` also writes the golden test's one-off reference characters `godot/tests/golden/ref_<slot>_<id>_<facing>.png` (the intern sheet with the accessory as an ordinary measured layer above Hair; 46 KB each, a `.gdignore` keeps them out of the importer). In a worktree: `ROOT` override as for the other tools.
- **Runtime** (`HeadGear`, `scripts/head_gear.gd`): a Node2D child of the body `AnimatedSprite2D` named `HeadGear`, created by `Look.apply` (so the player's `_load_character`, `npc.gd` `_ready` with `custom_look`, and the select preview, which calls `Look.apply`, all get it with no change to them or to `charselect.gd`); it draws above the body and below the held items and the headset (siblings added later). One `Sprite2D` per slot (`SLOTS`: beard under glasses; hats later) that NEVER plays an animation: it reads `sprite.animation` and `sprite.frame`, maps them with `HELD_ITEM.START` (the one shared table from `held_item.gd`, no copy), sets `region_rect = Rect2(idx * 32, 0, 32, 32)` and `position = sprite top left + origin[idx]` (the sprite's own offset and size are read, so a scaled preview works), uses the sheet of the animation's facing (no flipping) and hides while the animation has no `START` entry. It resyncs on `frame_changed` and `animation_changed` at once (no lag whatever the process order) and in `_process`, which also notices a changed `Look.look` / `Look.acc` (a hash) and rebuilds its materials. Backwards `sitdown`, one-shots, `pause()` with a hand-set frame (the jump) and `_switch_character` need nothing special: they only change `animation` / `frame` (`_switch_character` calls `Look.apply` through `_load_character`, which turns the overlay off for a stock person).
- **Adding an accessory** (a style of glasses or facial hair): draw it as a new layer `<slot>_<id>` in `office/accessories.aseprite` (right-facing, source colours above), add the id to `Look.ACC_STYLES[slot]` (look.gd and make_godot.py), run `make_head_sheets.lua`, `Godot --headless --path godot --import`, add the files, update the style list assertions in `tests/accessories.gd`. A new SLOT (hat ...) also needs a `SLOTS` entry in `head_gear.gd` at its draw height and a new `Look.ACC_STYLES` list; for a hat add `Look.HAT_HAIR` (the hair fallback rule); the accessory flag already keeps it out of the union shift. A new colour needs a `Look.SOURCES` row (0.06 RGB or more from the KEEPS and the other sources) and an update of `_sheet_colors` in `creator.gd` if it comes from a new sheet kind. Any change to `poses.lua` or `anim.lua` needs the head sheets rebuilt (the golden test says so).
- Tests: `tests/accessories.gd`, `tests/accessories_shots.gd`.
- **Not done**: brows following the hair colour.

### Character creator level 3 steps b (UI), c and d: the create rows, hats, nametag, lanyard and watch (roadmap R15; `scripts/look.gd`, `scripts/head_gear.gd`, `scripts/charselect.gd`, `scripts/career.gd`, `tools/make_head_sheets.lua`, tests `tests/accessories.gd`, `tests/layout_audit.gd`)
- **Create rows**: `CREATE_PAGES` in `charselect.gd` has two more pages, all rows of the new kind `acc` (`{"kind": "acc", "id": <slot>, "label": ...}`, `Look.cycle_acc` on Left / Right, chips like a choice row, so keys, pad and mouse work through the same `_create_change`): EXTRAS (GLASSES, BEARD, HAT) and WORK (NAMETAG, LANYARD, WATCH); wide fits tabs + 5 rows + the bottom row, so three rows a page. The box shows `Look.acc_title(slot, id)` (NONE first; a patchable `Career.UNLOCKS` title for glasses, beard and hat, `Look.ACC_TITLES` for the rest), a hat or glasses row with locked styles shows `N LOCKED` beside the chips, and the cycle only visits styles the player may wear. The preview wears it at once (`Look.apply` makes the `HeadGear`; `_refresh_look` swaps the sheet when a hat changes the hairstyle). RANDOM (`Look._randomize_acc`, drawn after every old draw, `Look.RANDOM_SHARE` a chance per slot, never a locked style) rolls accessories too. Presets still hold only the look dict, not `acc` (loading one keeps the accessories you wear). `layout_audit.gd` has `creator style hat`, `creator page 2/3 row 0/2` per format.
- **Hats (6)** `beanie`, `cap`, `hardhat`, `santa`, `bucket`, `party`; art is a silhouette plus a paint rule in `tools/make_accessories.lua` (ink outline added to every pixel with an empty 4-neighbour), drawn over the intern's hair crown (y 0 to 10; the party hat is a small cone ON the hair). - **`Dash`** (`dash.gd`, a static `RefCounted`, no autoload: `const Dash := preload(...)`; a test must `load()` it at run time because it reads the autoloads) is the record: `days` = `[{d, opened, closed, missed, hours: {who: h}}]`, a rolling window of 21 (`Dash.WINDOW`), the last entry is always today. Hooks: `Msp.create_problem` / `create_internal` (opened), `Msp.close_ticket` (closed), the SLA breach in `Msp._process` (missed), `Owner._work_queue` (hours of "CREW"), `Service._work_tech` (hours per tech). `Campaign._begin_day` calls `Dash.begin_day`, `Msp.reset` calls `Dash.reset`, the campaign save (and so the mid-day resume file) has a `dash` section; an old save loads empty (zeros, never invented). `Dash.recent(14)` pads short histories in front with empty days.
- **`Dashboard`** (`dashboard.gd`, static): `tiles(mode)` (ten tiles per mode: `{id, label, value, text, status g|o|y|r, digits, kpi}`) and `series(mode)` (`[left, right]` charts) are pure data; `paint(canvas, rect, mode, t, opts)` draws rectangles and polygons only: 14-segment LED digits (`digit()`, 12% ghost segments, red tiles pulse, blinking colon), 3D-ish bars (front, lighter top, darker side, grow in over 1 s), bezel tiles with a label. `layout(rect)` picks wide (width >= 230, height < 140: tiles 5x2 and ONE chart that rotates every 6 s or swaps on Enter / click), h (height >= 140: two charts side by side) or v (width < 230: tiles 2x5, charts stacked). Left chart: open tickets by client (tech), EBITDA by week (owner), pipeline by stage (sales), hours per tech today (service; cozy Easy shows the queue chart instead: no worst-tech bar). Right chart: opened / resolved of the last 14 days. Own title "PIXEL IT METRICS", invented tile labels.
- **Cozy Easy**: no red anywhere (a red tile and the TV flash are amber, `status_color`), the day score and EBITDA never show a minus. **Owner KPI ticks** on W-2 % (target 55), A/R OWED (under $1,500) and CLIENT MOOD (75 or more): a green check when met, an amber dash when not; the tile of the peer goal (`Owner.goal.id`) gets a yellow bezel. The owner board has CLIENT MOOD instead of TEAM SPEED so the three targets all have a tile.
- **Computer**: app `dash` (icon METRICS in every mode, a red-tile count as its badge, start menu entry; a long start menu goes in two columns). `Computer.dash_t`, `dash_chart`, `tv_mode`; code lives in `Dashboard.paint_app`. Offline at a desk with no network like every app.
- **Wall TV**: the `tv` fx got a fourth "micro" channel (`Dashboard.paint_micro`: four status blocks and a 6 day sparkline), and E on it (`interact.gd`) calls `Computer.open_tv()`: the same board full size under the faded strip, read only (no taskbar), Esc or a click on ESC CLOSES. The cubicle area got its own TV (`P.tv()` at 282,30 in `tools/build_sets.lua`, BGFX `("TV", "tv", 281, 29, 300)`; the framed notice moved to x 264). **Glance hint**: while any tile is red the TV frame flashes (`fx.gd _tv_tick`, once a second) and once a day `Hints.toast` names the tile (`Dash.glanced`).
- **Escalations trend arrow**: tech and owner boards have an ESCALATIONS tile (it replaced tech REOPENED and owner OPEN TICKETS; SLA breaches and reopens are already counted by `Growth.note_escalation`, so the SLA BREACHED tile stays) with a `trend` field and a 5x7 px arrow in its top-left corner (`Dashboard._arrow`, rectangles only; `ARROWS` table). `Growth.esc_trend()`: this period (tech: the 5 day week, owner: the week) against the last, pace-adjusted while a tech week runs (last week x days-so-far/5); 1 up = bad (red, amber on cozy Easy), 0 flat (yellow), -1 down = good (green); a difference under one escalation is flat. Not on the service or sales boards. Shots: `dash_shots.gd` sets 6 last week and 7 now (tech: up) or 1 now (owner: down).
- **Day report**: a 14 day opened / resolved sparkline (`DayReport._spark`) fills the spare room under the grade box in the wide layout (narrow: only when there is room); nothing when no day is recorded.

"tools/build_sets.lua")`. Never run `make_godot.py` in the real tree: run `check_generator.py --keep --scratch DIR` and copy the changed scene out of DIR (done for `cubicle_area.tscn` and `world_data.gd`).
